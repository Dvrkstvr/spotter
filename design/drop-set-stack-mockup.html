Spotter · session ledger

One set, however many lines it took

The stack with the delta on it — and the thing that makes the stack the right answer rather than a nicer drawing: a drop has no tick of its own, because it is not a set being logged. It is a set still being finished. Which moves the tick from the row to the set, and that is the change with teeth in it.

What one tick per set decides for you
  • Adding a drop re-opens the set. If the tick belongs to the set and the set is not over, the tick comes off — which is exactly what pressing + Drop set means: I'm not done with this one. Nothing else in the app has to learn a new state; the block is simply unticked again, and one tick at the bottom of the chain seals the whole thing.
  • A drop stops counting as a set, everywhere. The progress bar, 3 of 4 sets, the Finish button's hold, and the diary's 4 sets all count rows today, so one drop makes a four-set exercise say five. Under this model they count stacks, and the number goes back to being the one the routine asked for.
  • Volume still counts every line. A drop is work performed — 50 × 8 is 400 kg whatever it is part of — so totals() keeps adding it. Sets are a count of efforts; volume is a measure of work, and only one of them is affected by the regrouping.
  • Marks stay per line, ticks go per set. Each line keeps its own left cell, so a verdict on the drop and a verdict on the working set are still two different things you can record. That was the open question against the stack in the last mockup, and one-tick-per-set is what answers it.

3 · What changes underneath

No stored shape moves — link?: true on a LoggedSet is still the whole model, and the delta is derived from the line the chain hangs from. What moves is what a set means to the six places that count them.

WhereTodayUnder one tick per set
totals().all / .done every row, drops included skip linked rows — a drop is not a set
totals().vol every ticked row unchanged — every line is work performed
the tick box one per row one per stack; writes done to every line in it
+ Drop set inserts a row inserts a row and unticks the set it hangs from
the diary's n sets e.sets.length — counts drops counts unlinked rows; old entries re-report, nothing stored changes
superset.ts · whose turn a live linked row makes the turn yours outright, because a drop was two sets that both had to be yours the special case goes away — a drop is one set now, so counting stacks is already right
the mark sheet's remove unticked rows only same rule, one scope up: the stack is unticked or nothing in it leaves
lastLog / saveAsRoutine already working-sets-only, as of this week unchanged — they were fixed for exactly this reason
Three things I'd want you to say yes to before I build it
  • Adding a drop takes the tick off. It is the only place in the app where a tick comes off without you tapping it. I think it is right — the set genuinely isn't over — but it is the one thing here you will feel on the phone before you can judge it.
  • Deleting a set that has drops under it deletes the drops. They are lines of that set; there is no set for them to belong to afterwards. The alternative is promoting the first drop to be the set, which quietly rewrites what you lifted.
  • The diary's set counts on past sessions will change. A day that said 17 sets may say 15 tomorrow. Nothing stored moves and the new number is the truer one, but it is history changing its mind, which this app otherwise never does.
  • The delta is doing the job you described. −15 then −25 against reps of 8 then 6 is a readable fatigue curve — how much the weight had to fall for the muscle to keep producing reps. That is also an argument for measuring it from the top of the chain rather than line to line: the reference has to stay fixed for the numbers to be a curve.
  • Nothing new crosses to a buddy, and nothing needs a version bump. BuddyProgress carries done per row; the lines of a stack share their parent's, so the wire is unchanged and an older build simply draws the rows flat.
