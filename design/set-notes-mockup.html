Spotter · mockup

A note is a fact about the set.
Keep it with the set.

A set mark already draws a slim line under its row — but only once words exist, and only for as long as the session does. Nothing carries a note into the diary. HistoryEntry.list stores "70 × 8" strings and nothing else, so the one screen that is a record shows the numbers and drops what you thought about them. What survives is lastMarks — resurfaced next week as Last time · grip went first on the matching row, which is useful and is not the same as remembering.

What this mockup decides
  • In the session, the line arrives with the tick. A set that has been lifted can be judged; one three rows down cannot. So every done set carries the slim line — the note when there is one, a dim way in when there isn't — and untouched rows stay bare.
  • Last time's verdicts hoist to the top of the exercise. Whole, each naming its set, read before set 1 — where advice can still change what you do. They leave the set row entirely rather than being drawn in both places.
  • In the diary, an annotated set leaves the wrap. Sets keep flowing loose and wrapping; the one carrying words takes its own full-width line, glyph then note, in order.
  • The shape change is one optional field. LoggedExercise.marks?: (MarkNote | null)[], index for index with sets — additive, so no STORAGE_VERSION bump and no migration, exactly as list / secs / vol were added.
  • No new tip. The mark sheet is precisely the thing a careful person could use for a month and never find — and the catalogue's own rule is that the honest fix is usually the control. This is the control.

  • One slot, three tenants, one precedence. The line under a row can be last time's advice, this set's own words, or the way in — never two of them. Own words win, then last time's, then the affordance: once you have written something, your own sentence is the live fact and the ghost of last week is spent. That is the rule the current code already implies by rendering both; making the slot single is what stops a live row growing to four lines when the rest countdown is under it too.
  • The empty line is the quietest thing on the screen — neutral700, 11px, the note glyph the mark sheet already uses. It is dimmer than the ghost figures beside it, which is right: it is an offer, and everything else on the row is the workout.
  • It borrows no outline. Per the tip rules — no fill, no dash, no box. A note line is text and a glyph, so it can never be mistaken for the held control the dashes mean.
  • The tap target is the whole line, at slop. The index digit stays tappable — it is how you mark a set without words — but it stops being the only way in, which is the actual complaint.
The cost of B, stated
  • An 8-set exercise: 8 × ~16px = 130px of vertical, six or seven lines of it reading + Note. The set you are on gets pushed further from the thumb every set you finish, and the ledger stops scanning as a column of numbers.
  • C pays the same 16px only where a set has been performed, so the cost grows exactly as fast as the reason for it does — and an exercise you have just started still opens as a clean ledger.

  • A mark with no words shows the glyph and stops there. 70 × 8 ▲ — the verdict is a fact about the set and worth 4px of glyph, and it does not need to break the wrap to say so. Only words earn a full-width line.
  • Read-only, like everything else in the day panel. No editing a note six weeks later: the panel is a record, and the one thing it already lets you write — + Save as routine — writes a new object rather than rewriting the day. A note is what you thought at the time, and a diary that lets you revise that is worth less.
  • The glyph is neutral500, not accent. In the session the mark is accented because it is live and yours to change; in the diary it is history, and history is written in the same greys the figures beside it are.
  • Nothing else on the card moves. Same logSets container, same columnGap: 14, same loggedLine for the figure — the annotated set is one item in that wrap with flexBasis: '100%'.
Two alternatives, and why not
  • Notes gathered at the foot of the exercise — ▲ set 3 · bar felt light under the whole wrap. Keeps the figure row perfectly compact, and pays for it by making you count sets to find out which one is being talked about. Fine for one note, unreadable for four.
  • Glyph inline, note behind a tap — 70 × 8 ▲ and press to reveal. That is what the app does now, one screen over, and it is the thing being fixed: a note you have to go looking for is a note you don't read.

5 · The shape

One optional field, index for index with the sets it describes — the same relationship lastMarks already has to lastLog, and the same reason it has to be kept in step: a ▲ that slides one row is a verdict on a set that never earned it. 

// src/store/workout-store.tsx
export type LoggedExercise = {
  ex: string;
  sets: string[];
  /** Each set's verdict, index for index with `sets`. Optional, so every
      entry logged before this keeps its numbers and simply says nothing. */
  marks?: (MarkNote | null)[];
};
  • Additive, so no version bump. PERSIST's rule is that a new optional field inside an existing key costs nothing — this is the argument that let list, secs, vol and buddy all land on HistoryEntry without a migration over real training data. STORAGE_VERSION stays 4.
  • finishSession writes it beside lastMarks, from the same loop, filtered to ticked sets exactly as sets is — the two arrays are built together or they cannot be index-for-index.
  • A backup carries it for free (the durable slice), and mergePersisted needs no change: notes ride inside history, which the sessions part already moves whole, keyed by historyKey. The key is over date / rid / name / secs / vol, so adding notes cannot split one session into two.
  • It still never leaves the phone. A buddy snapshot carries no history at all, and BuddyProgress stays done booleans — what you thought of your own set is not the buddy's business, before or after this.
  • The statistics don't read it. stats.ts takes volume off each entry's own vol and never parses set strings except for distanceKm; notes are prose and there is nothing in them to count.

7 · What was settled

Built as drawn
  1. C, not B. The line arrives with the tick and stays for good. B is one boolean away if the offer turns out to be wanted on rows you haven't reached yet — but an 8-set exercise pays 130px for it, six lines of which say + Note.
  2. One slot, not a stack. Own words, else the way in on a lifted set, else nothing. Last time's advice left the row entirely (§2) rather than sharing the slot — the live box can already be carrying a rest countdown or the buddy's turn.
  3. The diary is read-only. No editing a note six weeks on: the day panel is a record, and the one thing it already lets you write — + Save as routine — creates a new object rather than rewriting the day.
  4. Per set, not per exercise or per routine. The note rides on a SetMark, and heavier / lighter is a verdict about a weight — an exercise has three to five of those in it. A routine is a template that outlives every session run from it, so a note on one could only be timeless, and timeless per-exercise text already has a home in cueEdits. If a dated per-exercise note is ever wanted it is LoggedExercise.note?: string — additive, so waiting costs nothing.
Where it landed
  • src/store/workout-store.tsx — LoggedExercise.marks, written in finishSession's existing pass off the same ticked array that builds sets.
  • src/components/overlays/session-overlay.tsx — the row's single note slot, and LastNotes above the ledger.
  • src/app/(tabs)/plan.tsx — the annotated set leaving the wrap.
  • src/data/i18n.ts — addNote, both languages.
  • STORAGE_VERSION stays 4. Nothing migrates.
